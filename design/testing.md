Decision: The board is tested in four layers: rules, store and server tests; the bundled page in a hand-written fake DOM; the page in a DOM library (jsdom) against the real server, which runs every check that needs only the page's logic, its DOM and the board's rules; and the page in headless Chromium against the real server on a temporary data repository, which keeps what needs a layout (where a box lands, how wide it is, what a browser hides, hit-testing, scrolling) and the diagrams, where the last two layers run on a board generated from a seed whose shapes come from a survey of the real board and are each required by a test of the first layer, no real text being copied, and their click checks compare where the page lands with what is computed independently from the stored board by the rules module and the server's unread history, because five page bugs in one day passed the first two layers and a browser per check made the page, agent list and message checks 272 of the 806 seconds of the browser job ([Four test layers](../docs/design.md#four-test-layers)), instead of tests in the fake DOM alone, fixtures copied from the real board, or every page check in the browser.

Rejected:
- The fake DOM alone: rejected because it computes no CSS or real layout and its fixtures hold few real shapes.
- Fixtures copied from the real board: rejected because real board data never enters this repository.
- Every page check in the browser: rejected because each check starts a browser, builds a board and reloads the page, which put the page, agent list and message checks at 272 seconds of the browser job's 806 seconds, and a DOM library answers the checks that need no layout.
- happy-dom instead of jsdom: rejected because its gain was small in the prototype (1.59 seconds against 1.95 seconds for 144 tree-row clicks) and the style checks are written against jsdom's stylesheet objects.
