Decision: The board is tested in four layers: rules, store and server tests; the bundled page in a hand-written fake DOM; the page in a DOM library (jsdom) against the real server, which runs every check that needs only the page's logic, its DOM and the board's rules; and the page in headless Chromium against the real server on a temporary data repository, which keeps what needs a layout (where a box lands, how wide it is, what a browser hides, hit-testing, scrolling) and what the real diagram library draws, where the last two layers run on a board generated from a seed whose shapes come from a survey of the real board and are each required by a test of the first layer, no real text being copied, and their click checks compare where the page lands with what is computed independently from the stored board by the rules module and the server's unread history, because five page bugs in one day passed the first two layers and a browser per check made the page, agent list and message checks 272 of the 806 seconds of the browser job ([Four test layers](../docs/design.md#four-test-layers)), instead of tests in the fake DOM alone, fixtures copied from the real board, or every page check in the browser.

Rejected:
- The fake DOM alone: rejected because it computes no CSS or real layout and its fixtures hold few real shapes.
- Fixtures copied from the real board: rejected because real board data never enters this repository.
- Every page check in the browser: rejected because each check starts a browser, builds a board and reloads the page, which put the page, agent list and message checks at 272 seconds of the browser job's 806 seconds, and a DOM library answers the checks that need no layout.
- happy-dom instead of jsdom: rejected because its gain was small in the prototype (1.59 seconds against 1.95 seconds for 144 tree-row clicks) and the style checks are written against jsdom's stylesheet objects.

Decision: The checks of the page's diagrams run in the DOM layer against a stand-in for the diagram library, which the window gives the page when it asks for the library by address, and a model of the diagram boxes whose widths are the page's own stylesheet evaluated for a box of given width, while the checks that depend on what the real library draws (its labels and sizes, how it parses, how it names ids, what the strict level leaves of hostile text, the frontmatter it applies) or on a real layout (the width at real window sizes, the ends an enlarged diagram can be scrolled to, the native wheel) stay in the browser layer, because the page and the library meet at two functions, so what the page does with a diagram (its states and errors, when and how often it asks for the library, zoom, drag, toolbar, theme, repaint) can be checked without the library's text measurement, which only a browser gives, instead of the real library in the DOM layer, a drawing recorded from the real library, or every diagram check in the browser.

Rejected:
- The real library in the DOM layer with a text-measurement shim: rejected because the library takes the size of every node from text measurement, so a shim gives invented sizes and the checks of sizes and fit would still need a browser, and loading the library costs over a second for each window.
- A drawing recorded from the real library: rejected because it needs a recorded file in the repository and a browser to record it again at each upgrade of the library, and the page's doing does not depend on the details it would add, which the browser checks of the real library show.
- Every diagram check in the browser: rejected because 42 of its 56 checks are the page's own doing, which the stand-in answers, and the file took 190 seconds of the browser job.
