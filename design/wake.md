Decision: Every agent, the architect's conversation included, has a push stream of its own where the board keeps how far the stream was delivered and the client acknowledges an event after it printed it or a tool result carried it, and no call answers more than the events it was given, because an engineer calls the board all the time while it works and would otherwise answer events it never saw ([The wake streams](../docs/design.md#the-wake-streams)), instead of a stream where the client keeps the number of the last event and any call answers everything pushed so far, as the retired PM's stream did, or a receipt for each event that is sent with a tool call, which would resend every unanswered event on each connection and cost a call per event.

Decision: Every push kind, its fields, its recipient and whether a call answers it are one table, the board refuses any other kind or field set, and only an event that one session has to act on is pushed (the owner is told of a blocking card on the page, and format flags are seen by whoever wrote the item; the kinds that only the retired PM acted on are no longer made, see wake/routing), because each push is something one session has to act on, as the architect's rules and the engineer rules say, and everything pushed stays in the agent's context until it is compacted ([What is pushed](../docs/design.md#the-wake-streams)), instead of pushing the other checks.

Rejected:
- One rule for every stream in which any call answers everything, as the PM's stream had: rejected because an engineer calls the board all the time and would answer events it never saw.
- A receipt for each event, sent with a tool call after handling (the resource agent's earlier design): rejected because every unanswered event would be resent on each connection, reaching the agent's context several times, and each event would cost a call.
- Pushing the checks that are format flags: rejected because whoever wrote the item sees them.
