Decision: The store publishes one frozen snapshot of the board and a write copies only the collections it changes, and what is derived from the board is advanced incrementally (activity times in an index that a write advances, one rules object per snapshot and minute for all readers, and only the items a write affects re-derived and repainted), because each write used to copy the whole board twice and derive it about eight times, which cost 0.28 to 0.4 seconds of daemon CPU a write on the live board, a quarter of it garbage collection ([Write cost](../../docs/design.md#4-architecture)), instead of a deep copy and a full derivation on every write.

Decision: The owner's unread list is carried on over the commits of each new head from the walk of the newest earlier head with the same read cursor and read marks, a walked stop keeps its finished form while it is unchanged, and the page asks for the list with the version it holds and gets only how many of its stops stay and the stops after them, because walking the history from the cursor at every head and sending the whole list after every change cost a `set_tags` write 20 to 30 ms more of the daemon's CPU with the owner 4,000 commits behind, and that cost grew with how long the owner had not read ([Write cost](../../docs/design.md#4-architecture)), instead of the page deriving the list from the change events or the daemon pushing its change with every event.

Rejected:
- A deep copy of the whole board and a derivation from scratch on every write (the earlier design): rejected because of its measured CPU cost per write.
- The page deriving the unread list from the change events: rejected because the page would hold a second derivation of what the owner reads, needing the documents before each stop, and the two could part.
- Pushing the unread list's change with every change event: rejected because every write would then read the history before its event goes out, also when no page is open, to spare a request of a few hundred bytes.
