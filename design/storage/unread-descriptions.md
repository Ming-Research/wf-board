Decision: What a commit changed in a document, as the owner reads it (the summary and the counts of what in it is visible), is kept for the commits after the owner's read cursor in a file of the daemon's own in the data directory that git leaves out, loaded before the daemon serves, and a round at the start and every five minutes carries the unread list to the head under a budget of its own and writes the file when it described anything, because a description depends only on an immutable commit yet lived only in memory, so a restart made the first request describe every commit after the cursor again: on the live board 11,725 commits at about 107 KB read each, 3.3 times the 32 KB a commit a request may read, and about 80 seconds over five requests, two of them refused ([The unread list across a restart](../../docs/design.md#4-architecture)), instead of a larger request budget or a read of each file once, which leave a walk of tens of seconds after every restart.

Decision: The file carries a version that is raised whenever a description would read differently for the same two documents, and a test pins sample descriptions beside it, because a file of the old description would otherwise give the owner the old text for the commits it covers, while a version number costs no more than the startup cache's, instead of keying the file by a hash of the code.

Rejected:
- Keeping the descriptions in the startup cache: rejected because its one way to fail is a scan of the whole history (tens of thousands of commits), a description's format changes oftener than the replay's, and the cache is written on a timer of the commits while descriptions are made by walks.
- Walking once after each start with the page waiting: rejected because every merge of board code restarts the daemon, and each restart would cost the walk again (about 80 seconds on the live board), also when the owner is away and no page asks.
- Storing the walked list instead of the descriptions: rejected because the list depends on the owner's cursor and read marks, which move whenever the owner reads, while a description is the same for every reading state.
- Describing each commit when it is written: rejected because every write would pay for the owner's reading whether or not a page is open, as pushing the unread list with every change was refused.
