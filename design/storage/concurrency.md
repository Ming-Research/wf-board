Decision: A write that replaces text names the revision it read and fails on a mismatch with the current content in the error, while appends to a log and writes of a whole field (the plan, the targets, the tags, the difficulty, the dispatch records) carry no revision, stamp their times on the server and are retried against the latest item so that unrelated concurrent writes survive, and a whole-field write whose result equals the current state makes no commit, because the agents' main pattern was to read an item, append a line and write the item back with its version (five conflicts and several malformed calls in the transcripts), appends should never conflict, and a revision read is needless for a field that is replaced whole ([Data format](../../docs/design.md#5-data-format), [Changing things](../../docs/design.md#changing-things)), instead of a revision on every write.

Rejected:
- A revision on every write: rejected because appends would conflict, and a field replaced whole needs no revision read.
