Decision: A diagram is asked for the classic look, 8 px of padding in a box and 20 px between boxes and between layers, because on a synthetic role chart of the owner's flow charts this draws it 24% shorter (3214 to 2430 px) and a chart with three lanes 26% shorter (2443 to 1801 px) with every arrow still entering a box from above, and the owner wants a drawing that takes little room and keeps its text readable ([Diagrams](../../docs/design.md#7-the-page)), instead of the library's own look and gaps, or of dagre, which is a third shorter but draws 12 of the 28 arrows into the side of a box.

Decision: ELK takes the gaps between boxes and between layers from the diagram's own configuration (the page's, with the settings block at the diagram's start over it), on the graph and on every subgraph, and keeps a straight run of 12 px before an arrowhead, through a wrapper around the `layout` call of elkjs in the bundled library entry, because ELK does not read `flowchart.nodeSpacing` and `flowchart.rankSpacing`, the library writes fixed gaps into the graph it hands ELK, and the wrapper uses only the public call of elkjs and ELK's own option names, so it reaches the subgraphs too; a browser check fails when the gap between layers returns to the library's 40 px, which is what happens if the library stops calling ELK through that call ([Diagrams](../../docs/design.md#7-the-page)), instead of the settings the library publishes, a layout registered by the page, a patch of the library or a change sent upstream.

Rejected:
- The library's own look and gaps: rejected because a synthetic role chart is then 3214 px high and its boxes fill 16% of the drawing, so a page of such charts holds little and shrinking them makes the text unreadable.
- Only the settings the library publishes (ELK's layering strategies, merging edges, the classic look): rejected because they leave the height within 10% of the library's own and some make the drawing wider.
- Dagre as the layout: rejected because it draws 12 of the 28 arrows of the role chart into the side of a box, which the owner refused as a broken drawing, and right-angle lines do not change it.
- A layout registered by the page under the name elk around the library's own ELK drawing: rejected because it names a file inside the library whose name changes with each release and its entry for options reaches only the top graph, not the gaps inside a subgraph.
- A patch of the library's source: rejected because the repository would carry a patch and the tool that applies it, both redone against each release.
- A change to the library so that ELK reads the two settings: rejected for now because it publishes to others and whether and when it is accepted and released is not ours to decide; the wrapper is removed when the library reads the settings itself.
