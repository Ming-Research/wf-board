Decision: The agent list is built only from the board's own records, the per-session index of the last items each session wrote, the dispatch records on items, the runner's report on each item it holds and the runner's beats for the turns running, and never from the host machine, because the owner required that the board can run on another machine and keep the list, and the runner, which pushes its reports to the board, is the only place that sees the work between a session's writes ([Agent list](../../docs/design.md#agent-list)), instead of asking the host for its session list, reading its state files, running a reporter process of the list's own or hooks, or taking the last writer of an item alone.

Decision: A session is listed only when a dispatch record names it, and then for six hours after its last write or dispatch start, except the PM's and the architect's own sessions; its state word comes from the steps in progress on its two items (a wait text, working within 30 minutes of its last activity, may have stopped after that, and none for a review), and a row is expanded only when its session has an unfinished dispatch that is alive within the same six-hour window the item status uses, because alive is then defined once, a session that waits for CI or the architect writes nothing for an hour, and the board has no PM: only the architect and the programmers the board sends out work on it, and a session no dispatch record names is the runner, an architect's turn, the board itself, a session started by hand or a name written by mistake, none of them a programmer the board sent out; the 30 minutes are provisional and reopen if a working session is seen silent for longer, instead of listing every session that writes, hiding the rows that are not running or telling running by the time since the last write alone.

Decision: The runner's block lists every piece of work the runner holds, an open, unpaused item with the runner's report and an engineer dispatch that began with it within five minutes of the report's start, as one unfolded row each, in the whole view's words and time limits, and the older rows leave out the sessions it holds and the programs' session names, because the work between a session's writes is the runner's and its waits for CI, a card or the architect are what the owner opens the list to see, and a dispatch that did not begin with the report must not make a session the PM started later the runner's ([Agent list](../../docs/design.md#agent-list)), instead of unfolding only the rows with a dispatch alive within six hours, dropping the whole view's rows that the block repeats, or drawing every report whatever the dispatch.

Rejected:
- Listing every session that wrote: rejected because without a PM the sessions that wrote and have no dispatch record are the programs (the runner, the architect's turns it starts, the board's watch), sessions started by hand and names written by mistake (one wrote as `architect`), which the board cannot tell apart; with them the folded rows held more programs than programmers, and a session the board sent out always has a dispatch record.
- Excluding the programs by a table of their session names: rejected because a rule on dispatch records needs no table and also leaves out the names written by mistake and the architect's helper sessions, which no table would name.
- Asking the host for its session list or reading its state files: rejected because it ties the board to the machine.
- A reporter process of the list's own or hooks: rejected because they add a process or a Claude Code format to keep alive; the runner is not one, being the program that runs the engineers' turns and already reports their state.
- Taking the last writer of an item alone: rejected because it loses a session's earlier items when another session writes the same item, and it needs the step in progress to know whose item it is.
- Hiding the rows that are not running: rejected because an unclosed finished session could then not be found.
- Telling running by the time since the last write alone: rejected because a session that waits for CI or the architect writes nothing for an hour.
- Inferring running from a step in progress on its items: rejected because the board cannot tell whose step it is.
- Folding the runner's rows by the six-hour rule of the older rows: rejected because a job that waits for the owner overnight would fold, and that wait is what the owner most needs to see.
- Dropping the whole view's rows that the block repeats: rejected because the whole view answers what is left and who has nobody, by item, and is also the architect's tool; the two say the same words with the same limits because both call the same function and table.
- Drawing a runner report whatever the dispatch behind it: rejected because a report left from an earlier job would claim the session the PM started later on the item.
