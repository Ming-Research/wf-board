Decision: The architect's stream is an ordinary agent stream and every owner note that has been sent goes there, because one protocol and one set of state for each recipient follow the owner's rule that any agent is reached the same way, and judging which notes are about content is the architect's work ([The architect's stream](../../docs/design.md#the-wake-streams)), instead of a second stream with receipts of its own for the architect, a note pushed to two recipients, or another session forwarding notes.

Decision: When the oldest push that the architect's stream must give has waited undelivered for an hour, the board tells the owner once, and a delivery starts the count again, and only the architect's conversation takes the pushes of its stream, not the turns the runner starts and the owner's other architect sessions, which write under names of their own that start with the architect's name, because the owner is the only one who can see that the architect has stopped, and a turn or another session that took the conversation's pushes would hide its silence ([No receipt](../../docs/design.md#the-wake-streams)), instead of telling the owner nothing, or counting the calls of any session under the architect's rights as deliveries.

Rejected:
- A second stream with receipts of its own for the architect: rejected because it is a second protocol and a second set of state for one recipient, and the architect's calls would answer notes that it was never shown.
- Pushing each note to two recipients: rejected because two receipts for one note leave it unclear who handled it.
- Another session forwarding the notes: rejected because it would have to judge which are about content, and that judgment is the architect's.
