Decision: Responsibility belongs to the project and nowhere else: every write names its project as author, a write to an item must come from the item's project unless the writer is the architect, or holds the observer's credential, which writes items of any project, a session's name is recorded only as an observation of who wrote, and work that one project needs from another is reported to the architect, who creates the item in the project that delivers it and joins it to the needing item by a shared row, because the board's earlier per-item agent field was used on only 23 areas, handovers were never used, and session-prefixed keys named the wrong session after a handover ([What the data shows](../docs/design.md#3-what-the-data-shows), [Project responsibility](../docs/design.md#9-project-responsibility)), instead of per-project agent lists, an agent field on items, child handovers or an inbox into which one project files work for another.

Decision: New keys need not carry a session prefix, and existing keys stay, because the server refuses a duplicate key so the prefix prevents nothing, and after a handover it names the wrong session, while notes and logs cite the existing keys, instead of keeping the session prefix on new keys.

Rejected:
- Per-project agent lists, an agent field on items and child handovers: rejected because responsibility turned out to be per project and the fields were unused.
- An inbox into which one project files work for another: rejected because the architect already creates the item in the project that delivers it, so an inbox only adds one more record to keep; the board removed the inbox and its two tools.
- Session-prefixed keys: rejected because duplicate keys are refused anyway and the prefix names the wrong session after a handover.
