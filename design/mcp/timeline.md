Decision: A line is drawn for one agent, a dispatch record, from its start to its end (to now while it is open, to the end of the work when that comes first), whatever its role, and is made by one function, `lineOf`, from the item's state starts and its pause spans, so that an item which passed through several agents has several lines and the time before the first session and between two sessions is on no line; the `timeline` tool prints the lines while the runner's block of the agent list draws the line on the row of its agent, because the owner reads the list as agents and asks where each agent's time went, the time no session held is nobody's wait, and two derivations would give two sets of numbers ([Agent list](../../docs/design.md#agent-list)), instead of one line for a whole piece of work that marks the stretches with no session open, or a tool and a page block that each derive the segments.

Decision: A line has two kinds of stretch: work, a turn of the agent running, and waits between its turns that name what they wait for (CI, the owner's cards, the architect, other items, a 14900K run, an event, a merge, a person to look, wrap-up), the first stretch of a session being work whatever the state reported at its start, and a session the runner reported nothing in has no line, because the runner starts a session by starting a turn, a report made as the session begins is that turn's own, and a line drawn for a session the runner did not run would show work that nobody measured ([Agent list](../../docs/design.md#agent-list)), instead of drawing the item's states whole or leaving the first stretch to the state left over from the earlier session.

Decision: A state start is the `since` of a runner report, made by one function for the live write and for the history replay, kept per item in the activity index (the newest 500) and derived from the commits whose message begins `report_state `, because the runner's reports are already commits that the history holds (1463 of the 32978 commits of the live board when this was decided), a restart must give what live writes gave, and agents finished before this decision then have their lines without a second path and the item does not grow ([Data format](../../docs/design.md#5-data-format)), instead of a segment stored on the item at each report or a read of the item file's history for each request; the cap of 500 is provisional and reopens if a job is seen to pass it.

Decision: A stretch is drawn as long as the time it took up to three hours and a tenth of the time beyond, with a gap marked in it, and the stretches where the item was paused replace the state they were in, because one session lasts from minutes to days and the longest wait must still look longest while a week-long wait must not leave the day's work a pixel wide, and a pause is time the agent spent that the line should show and not hide ([Agent list](../../docs/design.md#agent-list)), instead of true scale or equal widths; the three hours are provisional until lines of the live board are seen.

Rejected:
- One line for a whole piece of work, with the stretches that had no session open marked: rejected because the owner asked to see each agent, not each piece of work, and a stretch with no session is no agent's wait, so it would be counted as a wait of nobody.
- Storing a segment on the item at each report: rejected because the item would grow with its reports as the log entry per report refused for the runner's report would, work finished before the change would have no line without a second path that fills it in from the history, and the past would be stored twice.
- Reading the item file's history for each request: rejected because an item file has hundreds of versions of tens of kilobytes, so one request would read tens of megabytes, and the page could not be told when a line moved.
- True scale: rejected because one wait of a week leaves the day's work a pixel wide.
- Segments of equal width: rejected because the longest wait would not look longest.
- A block of lines apart from the table: rejected because a title and its line would stand in two places.
- A line for each turn of the architect that answers an engineer, made from the runner's beats: rejected because the beats live in memory only; the wait stays one stretch of waiting for the architect on the engineer's line, and the architect's turns get lines of their own when the board holds a dispatch record for each.
