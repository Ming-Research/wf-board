Decision: The candidates read lists every item that can be started and that nobody holds, in one default order (first the item that more open, unpaused work items hold a shared row for, then the earlier item number), and chooses nothing, where an item is held while an open engineer dispatch record is on it, even a quiet one, so that a second engineer is not started beside a stopped one, because choosing among candidates, by any principle, is the architect's work and not the board's ([The candidates read](../../docs/design.md#finding-things)), instead of the board naming the next item.

Decision: After each pool's candidates, apart from them and outside their count, the same read lists the rated items nobody holds, with no open sub-item, that cannot be started now for a reason the board can name: paused work, where a row says who paused it, when, for how long and why and more than three items under one pause marker are one row with the count, and todo or idle work that cannot be started now (mostly work in a backlog, or work whose next step carries a wait text) whose head has a start-condition section, where a row gives the first sentence of it and how long since the item last changed and more than three under one parent are one row with the count, at most ten rows for a pool taken a project at a time, because the queue is refilled from this read and the six items of one project that the owner's changed principle had made startable stayed unseen while only the startable ones were listed, and a project with hundreds of paused items must not crowd out one with a few ([The candidates read](../../docs/design.md#finding-things)), instead of a separate tool for paused work or listing it among the candidates.

Rejected:
- The board naming the next candidate: rejected because the choice is the architect's.
- A separate tool for paused work and work with a condition: rejected because the caller who refills the queue makes one call, and the gap was a read of the candidates alone, so a second call would again rest on memory.
- Paused work and work with a condition counted as candidates and marked: rejected because the architect compares the candidate count with the owner's numbers, and an item that cannot be started would be counted as one that can.
