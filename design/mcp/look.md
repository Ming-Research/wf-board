Decision: The look answers in one call where all the open work stands, as the tree the owner's board shows (each project's top items and what they own, one line for an item) in a budget of lines the caller sets, spent by opening first the subtrees that hold an item nobody holds or that waits too long, then work being done, then a check flag, then a pause, where a pause marker makes its subtree one line with the reason and how long, the work of a project's backlog is counted apart, and every open work item is a line or inside a count on a line, because the architect assembled the board one item at a time (1,193 `context` calls in eleven sessions) while each read that shows a whole showed a corner, and an item left out of the one view the architect uses is work it forgets (six paused items missed when the queue was filled) ([The look](../../docs/design.md#finding-things)), instead of a longer `whole_view` or a flat list of every item.

Decision: What a session saw at its last look is kept in the daemon's memory, one signature for each open item (its revision, its status and its checks) for each of at most sixteen sessions, and the next look of that session marks the items whose signature differs, the new ones and the number that finished, where a look at some projects updates only their signatures, because a signature shows the changes no write made (an item stops waiting when what it waited on is done), which are the changes the architect fills the queue by, and a read must not write to the data repository ([The look](../../docs/design.md#finding-things)), instead of the time of the last look compared with each item's update time or a commit written for each look.

Rejected:
- A tree option on `whole_view`: rejected because the owner's page draws the same function's five kinds, and one tool with two answers has parameters that contradict each other (`bucket` and `expand`) and drifts from the page.
- Remembering only the time of the last look: rejected because it cannot mark a change no write made, and marks wrongly an item written in the same second as the look.
- Writing each look to the data repository: rejected because it turns a read into a write through the write queue and grows the history with every look.
- Listing every item: rejected because on a board of 1,600 items the answer would fill the caller's context; the budget makes its size the caller's choice.
