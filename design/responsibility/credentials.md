Decision: Who is writing is told by a bearer credential on the connection: a random token that the board keeps only as a SHA-256, issued once to a dispatched session by the dispatch tool, bound to the dispatch's session, role, root item and project and removed when the dispatch finishes, or, for the architect, the PM, the observer and the resource agent, listed as hashes in a file outside the data directory that the service only reads, and a valid credential overrides the names a call gives while an invalid or revoked one is refused on every call, reads included, and never falls back to the named way, because a caller that names its own project and session can name them wrongly or borrow another's, and a revoked session that still names an author would otherwise keep writing ([Credentials](../../docs/design.md#credentials)), instead of trusting the names a call gives. The credentials guard against a wrong or borrowed name by mistake, not against an agent on the Mac that reads another agent's configuration on purpose.

Decision: A session receives its credential in its own MCP configuration file, because a resumed background session reads that file again, a background session does not receive the environment of the command that started it, and a per-directory MCP configuration applies to the whole repository and its worktrees and redirected other sessions' connections (all tested), instead of an environment variable or a per-directory configuration.

Rejected:
- Trusting the project and session names that a call gives: rejected because they can be wrong or borrowed and nothing in the call tells.
- Falling back to the named way when a credential is invalid: rejected because a revoked session that still names an author would keep writing.
- Passing the credential in an environment variable: rejected because a background session does not receive the environment of the command that started it.
- A per-directory MCP configuration: rejected because it applies to the whole repository and its worktrees, so it cannot give each session its own credential, and it redirected other sessions' connections.
- Recording the credential per MCP session: rejected because the endpoint keeps no session.
