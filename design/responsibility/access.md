Decision: What each role may write is one table from role to the parts of the board a write changes, each with a scope (the whole board, a subtree, below its root, or its own), and the one path every write takes is given the parts of its write as an argument, because then no write can leave them out, and a list of allowed tools per role would have to be kept in step with every new tool and with the side effects a tool has on other items, and a missing entry would stop nothing, and that path refuses a part the role lacks before it reads anything and, for the subtree scopes, checks after the write is built that every changed document, the board's own side effects on other items included, is inside the subtree ([Credentials](../../docs/design.md#credentials)), instead of a list of allowed tools for each role.

Rejected:
- A list of allowed tools for each role: rejected because it must be kept in step with every new tool and with the side effects a tool has on other items, and a missing entry stops nothing.
