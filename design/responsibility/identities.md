Decision: The architect is the author `Architect` writing from any session name that starts with the name for the architect, the exact name being the conversation the owner talks to and the longer names the runner's turns that answer an engineer and the owner's other architect sessions (an observing one, one that tidies old projects), and those names are reserved (a credential of another role under them and a dispatch of an engineer or a review for them are refused, while the record of an architect's turn, which has no credential, may carry one), because the author name is also a project whose own engineers write as that author, so the author name alone cannot tell a project's engineer from the process role, and the owner starts a new kind of architect session now and then, which then needs only a name and no change to the board, instead of the author name alone as the identity or a fixed list of architect names ([Project responsibility](../../docs/design.md#9-project-responsibility)).

Decision: The architect's rights and the pushes for the architect are separate tests: every name that starts with the architect's name has the rights, while the pushes and the exclusion of the architect's own writes from its timed wake go by the conversation's exact name alone, because a turn or another architect session must write with the architect's rights, and under the conversation's name it would be carried the conversation's pushes and mark them delivered, and a name of its own tells in the history which architect wrote ([The architect's sessions](../../docs/design.md#the-wake-streams)), instead of those sessions writing as the conversation, a role of its own for them, or the runner writing the answers itself.

Decision: The runner, the resident program that starts the engineers' turns and reports their state, writes as the author of the item's project from the session named for the runner and over no credential, and that session may do one part of the process, reporting the runner's state on an item, while its name is reserved like the architect's names and is read only when no credential is carried, because the runner has no credential, so the board can tell it only by its name, and it must report at every turn without taking the pushes that the architect's names carry, and the two dispatch tools it also calls need no rule of their own, since without a credential they check only the item's project, which grants nothing beyond what that project's author may write, and the credential's role table gives them to the process alone ([The runner](../../docs/design.md#9-project-responsibility)), instead of a credential of a role of its own for the runner, opening the report to every project author, or the architect's credential.

Decision: Writes under the retired coordinator author and the retired PM author are refused by the one path every agent write takes, with a message naming the architect, who does the process and keeps the rules, while the two projects stay configured so that their items, glossary and history remain readable, and the PM has no role in the credential file and its session name is an ordinary name, because the pushes that made the PM a role are gone and the author name `PM` has no verification, so any session could use it to write the whole process ([The PM is retired](../../docs/design.md#the-pm-is-retired)), instead of leaving the author name usable, leaving the PM's role in the credential table for a PM that may return, or keeping the PM's identity after its pushes and stream are gone.

Rejected:
- The author name alone as the identity of the architect: rejected because the author name `Architect` is also a project whose engineers write as that author.
- A role of its own for the turns or for each kind of auxiliary architect session, with a narrower access table: rejected because a turn does the architect's whole work (answering, cards, pauses, new items, ratings, the architect's journal), so the narrower table is either the architect's or stops a turn the next time a part is added, each new kind of session needs a table of its own and each new board operation a decision in every table, and a credential guards against a wrong name, not against impersonation, so least privilege buys little.
- The turns writing as the conversation, with the pushes kept by another mechanism: rejected because the board would still need a name or a credential to tell the turns apart, which is the chosen decision with an extra layer, and a flag on each call cannot be set by the runner for calls the model makes.
- The runner writing the turns' answers with its own session: rejected because it would translate each of the architect's judgment writes into a format it understands, and it would need the architect's rights itself.
- A credential and a role of its own for the runner: rejected because the runner stays refused until the owner has issued a token and put it in the runner's configuration, and the path without a credential would still need a rule for the runner until it is removed; it can be added beside the name later, since the two do not conflict.
- Opening the report to every project author without a credential: rejected because any session could then write a false state on any item of its project, and the whole view reads that state to tell what each item waits for.
- The architect's credential for the runner: rejected because it would carry all of the architect's rights for the one part the runner needs, and the runner's calls would be taken for the architect's.
- One shared name for every auxiliary architect (the turns' name for all): rejected because the board then shows the runner's turns and the owner's other architect sessions as one writer, so the last writer on an item no longer says which architect wrote, and the name was defined as the runner's turns.
- Auxiliary architect sessions as ordinary project authors, the conversation's architect writing for them: rejected because they could not create items in other projects, retitle, issue cards or write the architect's log, and the conversation's architect would relay every such write, which is the work the owner opened the other sessions to take off it.
