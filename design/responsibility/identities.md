Decision: The architect is the author `Architect` writing from one of two session names, the one named for the architect, for the conversation the owner talks to, and the one named for the architect's turns, for the turns the runner starts to answer an engineer, and those two session names are reserved (a credential of another role under them and a dispatch for them are refused), because each author name is also a project whose own engineers write as that author, so the author name alone cannot tell a project's engineer from the process role, instead of the author name alone as the identity ([Project responsibility](../../docs/design.md#9-project-responsibility)).

Decision: The architect's rights and the pushes for the architect are separate tests: both session names have the rights, while the pushes and the exclusion of the architect's own writes from its timed wake go by the conversation's name alone, because a turn must write on the engineer's item with the architect's rights, and under the conversation's name it would be carried the conversation's pushes and mark them delivered ([The architect's turns](../../docs/design.md#the-wake-streams)), instead of the turns writing as the conversation, a role of its own for the turns, or the runner writing the answers itself.

Decision: The runner, the resident program that starts the engineers' turns and reports their state, writes as the author of the item's project from the session named for the runner and over no credential, and that session may do one part of the process, reporting the runner's state on an item, while its name is reserved like the architect's two and is read only when no credential is carried, because the runner has no credential, so the board can tell it only by its name, and it must report at every turn without taking the pushes that the architect's names carry, and the two dispatch tools it also calls need no rule of their own, since without a credential they check only the item's project, which grants nothing beyond what that project's author may write, and the credential's role table gives them to the process alone ([The runner](../../docs/design.md#9-project-responsibility)), instead of a credential of a role of its own for the runner, opening the report to every project author, or the architect's credential.

Decision: Writes under the retired coordinator author and the retired PM author are refused by the one path every agent write takes, with a message naming the architect, who does the process and keeps the rules, while the two projects stay configured so that their items, glossary and history remain readable, and the PM has no role in the credential file and its session name is an ordinary name, because the pushes that made the PM a role are gone and the author name `PM` has no verification, so any session could use it to write the whole process ([The PM is retired](../../docs/design.md#the-pm-is-retired)), instead of leaving the author name usable, leaving the PM's role in the credential table for a PM that may return, or keeping the PM's identity after its pushes and stream are gone.

Rejected:
- The author name alone as the identity of the architect: rejected because the author name `Architect` is also a project whose engineers write as that author.
- A role of its own for the turns, with a narrower access table: rejected because a turn does the architect's whole work (answering, cards, pauses, new items, ratings, the architect's journal), so the narrower table is either the architect's or stops a turn the next time a part is added, and a credential guards against a wrong name, not against impersonation, so least privilege buys little.
- The turns writing as the conversation, with the pushes kept by another mechanism: rejected because the board would still need a name or a credential to tell the turns apart, which is the chosen decision with an extra layer, and a flag on each call cannot be set by the runner for calls the model makes.
- The runner writing the turns' answers with its own session: rejected because it would translate each of the architect's judgment writes into a format it understands, and it would need the architect's rights itself.
- A credential and a role of its own for the runner: rejected because the runner stays refused until the owner has issued a token and put it in the runner's configuration, and the path without a credential would still need a rule for the runner until it is removed; it can be added beside the name later, since the two do not conflict.
- Opening the report to every project author without a credential: rejected because any session could then write a false state on any item of its project, and the whole view reads that state to tell what each item waits for.
- The architect's credential for the runner: rejected because it would carry all of the architect's rights for the one part the runner needs, and the runner's calls would be taken for the architect's.
