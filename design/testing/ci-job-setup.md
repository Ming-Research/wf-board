Decision: Every job of the full CI that needs the packages (`check`, `test`, `nkey`) gets Node 24 and them from one action that restores `node_modules` from a cache keyed by the hashes of `package.json` and `package-lock.json` and runs `npm ci` only when the cache is not found, because 28 jobs run at once, so the set-up of the job that ends last is in the minute, and the set-up of a job (checkout to the build of the page) took 8.5 seconds at the median in 8 jobs that found the cache (7 to 10) and 12.5 in 12 jobs with the cache of npm (10 to 19), the restore costing 2 to 3 seconds where the cache of npm cost 2 to 3 and `npm ci` 5 to 6, the ranges overlapping at 10 and no noise floor measured ([The set-up of a job](../../docs/design.md#the-set-up-of-a-job)), instead of the cache of npm that `setup-node` restores followed by `npm ci`. Both files are in the key because `npm ci` refuses a `package.json` that disagrees with the lock file and a restored directory would hide that. Node 24 comes from the runner image's tool cache, put on the path, with `setup-node` only for an image without it, because `setup-node` also prints the versions of node, npm and yarn, which took 0.4 to 7.2 seconds (15 of 72 jobs over 2), and the Node on the path is 22 where the project runs on 24; the jobs run their scripts with `node --run`, not `npm run`, because the first start of npm in a job reads its files from the image's disk and took 3 to 14 seconds in 13 of 60 shards ([The set-up of a job](../../docs/design.md#the-set-up-of-a-job)). The job `result` has `setup-node` only: it runs a script that imports only Node's own modules, and starts with the run, so its set-up is not in the time.

Rejected:
- The cache of npm and `npm ci`: rejected because it costs 8 to 9 seconds in every job where a restored `node_modules` costs 2 to 3.
- No cache: rejected because `npm ci` alone took 7 to 9 seconds and the set-up 13.5 at the median, no better than with the cache of npm.
- `npm ci` with `--ignore-scripts --no-audit --no-fund --prefer-offline`: rejected because the set-up took 14.5 seconds at the median in 4 jobs, not shorter.
- The Node on the runner's path: rejected because it is 22, below the 24 the project's `engines` ask for.
- `setup-node` in every job: rejected because its print of the versions took up to 7.2 seconds where the image's own Node 24 costs nothing.
- `npm run` for the scripts of a job: rejected because the first start of npm read its files from the image's disk for up to 14 seconds, where `node --run` reads no npm.
- A history without file contents for the checkout of the n-key parts: rejected because the checkout was not measurably faster in the one run timed and the base page's files would come from the remote one change at a time (deduced, not tried).
