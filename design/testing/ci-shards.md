Decision: The script tests run in the full CI as eight shards at once, each test file dealt out longest first to the shard with the least cost so far, the cost of a file being the seconds of its own entry in the test runner's report on a hosted runner (from the start of its process to its end, which the sum of its tests leaves short), kept in a table in the repository, with a default cost for a file the table does not name so that a new test file is run from its first push, and the type check runs in a job of its own, because the suite took 82 to 118 seconds on one runner and its files take from 0.1 to 30 seconds ([Sharding the script tests](../../docs/design.md#sharding-the-script-tests)), instead of Node's own split by position or a hand-kept list of the files of each shard. The count of eight is provisional: 16 shards and a higher test concurrency were each tried once on hosted runners and shortened the longest step by no more than the spread between runs, the largest files bound a shard, and the choice reopens when those files are split.

Rejected:
- Node's `--test-shard`: rejected because it cuts the sorted list of files by position and three shards measured 21.6, 47.5 and 39.8 seconds of tests.
- A hand-kept list of the files of each shard: rejected because a new test file would belong to no shard and nothing would run it, which a default cost for an unnamed file cannot do.
