Decision: The script tests run in the full CI as twenty shards at once, each test file dealt out longest first to the shard with the least cost so far, the cost of a file being the seconds of its own entry in the test runner's report on a hosted runner (from the start of its process to its end, which the sum of its tests leaves short), kept in a table in the repository, with a default cost for a file the table does not name so that a new test file is run from its first push, and the type check runs in a job of its own, because the suite took 82 to 118 seconds on one runner, its files took from 0.1 to 33 seconds, and once the browser's checks had moved into it eight shards took 33 to 56 seconds of tests and a run 73 seconds against the 60 of the time gate; after the files of 25 seconds and more were split in two or more, a shard's step took about the sum of its files' seconds divided by three plus a second, so the count of shards sets the time: with sixteen the shard that ended last ended 49 to 56 seconds after the start of the run (median 53), with twenty its longest step took 27 seconds and its job 42 plus a wait of about 5 for a runner, and with twenty-four 25 and 41 ([Sharding the script tests](../../docs/design.md#sharding-the-script-tests)), instead of Node's own split by position or a hand-kept list of the files of each shard. The count is provisional: splitting the files raised the sum of their seconds from about 920 to about 1,090 because each page file builds its own board, and a higher test concurrency was tried once and was no faster, so the choice reopens when that sum changes much.

Rejected:
- Node's `--test-shard`: rejected because it cuts the sorted list of files by position and three shards measured 21.6, 47.5 and 39.8 seconds of tests.
- A hand-kept list of the files of each shard: rejected because a new test file would belong to no shard and nothing would run it, which a default cost for an unnamed file cannot do.
- Eight shards: rejected because with the suite at 906 seconds of file time the step `tests` of a shard took 33 to 56 seconds and the run 73 seconds, over the 60 the time gate allows.
- Twelve shards: rejected because the longest job took 61 seconds, over the line, where sixteen took 46 to 51.
- Sixteen shards: rejected because with the large files split the shard that ended last ended 49 to 56 seconds after the start of the run in four runs (median 53), over the 50 seconds that a typical run aims at, where twenty gave a job of 42 seconds plus a wait of about 5.
- Twenty-four shards: rejected because its longest job (41 seconds) was one second shorter than twenty's and each run needs four more jobs, each paying its own set-up of 10 to 15 seconds.
