Decision: The script tests run in the full CI as thirty shards at once, each test file dealt out longest first to the shard with the least cost so far, the cost of a file being the seconds of its own entry in the test runner's report on a hosted runner (from the start of its process to its end, which the sum of its tests leaves short), kept in a table in the repository, with a default cost for a file the table does not name so that a new test file is run from its first push, and the type check runs in a job of its own, because the suite took 82 to 118 seconds on one runner, its files took from 0.1 to 33 seconds, and once the browser's checks had moved into it eight shards took 33 to 56 seconds of tests and a run 73 seconds against the 60 of the time gate; after the files of 25 seconds and more were split in two or more, a shard's step took about the sum of its files' seconds divided by three plus a second, so the count of shards sets the time: with sixteen the shard that ended last ended 49 to 56 seconds after the start of the run in four runs (median 53), with twenty 46 to 51 seconds in five (median 50), and one run each of the same scripts in twenty-four shards and in twenty had the longest job 41 and 42 seconds ([Sharding the script tests](../../docs/design.md#sharding-the-script-tests)), instead of Node's own split by position or a hand-kept list of the files of each shard. The count is thirty because the suite is bound by the processor (951 seconds of CPU for 789 of wall time, a shard running four files no quicker than one running three), so the step of a shard follows its files' CPU and only more shards shorten it, and twenty left the time gate at 45 to 59 seconds in eleven runs (median 50) against the line of 60: with thirty shards, every file over about 15 seconds split and the test processes no longer held after their last test, two runs were judged 44 and 45 seconds ([Sharding the script tests](../../docs/design.md#sharding-the-script-tests)). The count is provisional: it reopens when the sum of the files' seconds (984 to 1,120 in those runs) changes much, or when the organization's 60 concurrent jobs make runs wait for runners.

Rejected:
- Node's `--test-shard`: rejected because it cuts the sorted list of files by position and three shards measured 21.6, 47.5 and 39.8 seconds of tests.
- A hand-kept list of the files of each shard: rejected because a new test file would belong to no shard and nothing would run it, which a default cost for an unnamed file cannot do.
- Eight shards: rejected because with the suite at 906 seconds of file time the step `tests` of a shard took 33 to 56 seconds and the run 73 seconds, over the 60 the time gate allows.
- Twelve shards: rejected because the longest job took 61 seconds, over the line, where sixteen took 46 to 51.
- Sixteen shards: rejected because with the large files split the shard that ended last ended 49 to 56 seconds after the start of the run in four runs (median 53), over the 50 seconds that a typical run aims at, where twenty ended it 46 to 51 seconds after the start in five runs (median 50).
- Twenty-four shards: rejected because its longest job (41 seconds, one run) was one second shorter than twenty's (42, one run) and each run needs four more jobs, each paying its own set-up (10 to 15 seconds when this was measured, 7 to 10 in 8 jobs that found a cache of `node_modules`, [The set-up of a job](../../docs/design.md#the-set-up-of-a-job)).
- Twenty shards: rejected because the time gate judged eleven runs at 45 to 59 seconds (median 50), leaving no margin under the line of 60 for a slow set-up, where thirty with the large files split were judged 44 and 45 in two runs.
- More shards without splitting the large files: rejected because thirty shards alone left the longest step at 26 seconds, the length of one file (`deploy.test.ts`), and the run at 46 seconds.
- A larger runner (eight cores): rejected because it is paid by the minute in every run, the fixed set-up and the result's lag of about 15 seconds do not shrink with it, and the largest file would still set the floor.
