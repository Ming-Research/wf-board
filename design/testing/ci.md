Decision: A push to a pull request branch does not start the full CI, which uses some twenty runners at once and which a change under way would start at every push: while writing, a temporary workflow runs only what the change touches, at the end the engineer merges the main line into the branch, deletes the temporary file and starts the full CI by hand, a check fails any full CI while a temporary workflow file exists, and the result of a run started by hand is written to the head commit as a status of its own, because GitHub did not list the checks of a run started by hand among a pull request's checks (observed on a test pull request), so the pull request would otherwise read as passed on the checks that did run ([Fast checks while writing, and the full CI at the end](../../docs/design.md#fast-checks-while-writing-and-the-full-ci-at-the-end)), instead of the full CI on every push. This is provisional and reopens if GitHub lists such runs among a pull request's checks.

Rejected:
- Reading the commit's check suites in the board instead of a status: rejected because it would fix the board only and not the pull request's own check list or the engineer's wait script.
- Starting the full CI by a pull request label: rejected because a label would have to be added and removed for each run and any other label would start it too.
