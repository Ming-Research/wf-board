Decision: The last job of a full CI started by hand reads the run's jobs through the Actions API and puts into the run's summary the seconds from the start of the run to the end of its last job, the time of each job and a table of the test shards that names a shard over 1.5 times the mean of the others, with the total yellow above 50 seconds and red above 60, and a red total fails the step and with it the run and its status, because a lane that slows down must turn something red or the minute for a pull request's checks is lost unnoticed, and two runs of one configuration differed by 13% so a typical 50 seconds leaves the line 20% above ([The time gate](../../docs/design.md#the-time-gate)), instead of limits on each job's own time alone, no gate, or a gate that only reports. The browser tests are a workflow of their own and not in this run, so the total is the script tests' and a red that never clears cannot happen.

Rejected:
- Limits on each job's own time alone: rejected because a lane can slow down by waiting, for a runner or for the job before it, with every job inside its limit.
- A table of times with no limit: rejected because nothing turns red when the run slows down, which was the state before the gate.
